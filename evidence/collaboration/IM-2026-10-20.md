# IM 重复展示修复与双账号线上验收 — 2026-10-20

用户在“项目协同 → 消息”发现输入一条显示两条，要求两个账号验证即时 IM。

## 复现及根因

在正式域名 https://collabspace.purelamp.uk，两个独立 Edge 浏览器上下文分别通过登录表单登录 owner@acme.dev / member@acme.dev，打开同一私聊。修复前发送一次，发送方产生两个气泡，浏览器断言明确收到 2 而预期 1（im-before.json）。读取同一条消息的服务端历史只有 1 个 ID / 1 条消息（im-duplicate-diagnosis.json），没有重置或删除用户消息。

发送接口响应与 Socket.IO im:message:new 广播均调用 appendMessage；旧实现直接追加，导致同一服务端消息 ID 在前端出现两次。

## 修复

- 前端消息列表按服务端消息 ID 去重，保留发送接口响应作为实时连接不可用时的展示途径。内容相同但 ID 不同的合法消息不会被吞掉。
- 发送期间通过同步 ref 阻止重复 Enter / 发送及附件入口再次发请求，避免仅依赖按钮 disabled。
