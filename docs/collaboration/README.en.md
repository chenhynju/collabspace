# CollabSpace

Reliable project documents for remote delivery teams. Built on an independently copied TeamSpace foundation: Next.js, React, NestJS, Prisma and PostgreSQL. This repository is private; no production deployment is implied.

## The product journey

Create a document inside a project, grant access to another organization member, edit together, discuss a selected passage, keep working through a network outage, reconnect and review an immutable delivery version. Recovering a version creates a private copy without overwriting active collaborators.

## What makes the implementation useful

- Yjs rich-text merging with Tiptap, relative cursor/selection positions and per-session presence.
- A dedicated native WebSocket process with a versioned, allowlisted protocol. Existing Socket.IO messaging remains separate.
- PostgreSQL commit precedes every successful update ACK. An opaque connection ticket is short-lived and consumed once. Idempotent update IDs survive lost ACKs.
- Shared authorization checks the account, organization, membership, project and document grant on every read/write. Parent row locks conflict with revocation and archival; tenant RLS is tested using a non-superuser role.
- IndexedDB atomically stores the local document and its pending updates. The UI distinguishes local persistence from confirmed server persistence.
- Relative comment anchors, orphaned-comment visibility, optimistic revisions and immutable versions. A restored copy gets a new CRDT lineage and a private initial ACL.

## Run locally

Requires Node 20+, pnpm and a dedicated local Redis instance. The local helper uses embedded PostgreSQL with synthetic data, never the original project's environment file.

```text
pnpm install --frozen-lockfile
pnpm local:up
```

Web: http://localhost:43120. API: http://localhost:43121/api/v1. Collaboration: ws://localhost:43122/collab. Synthetic PostgreSQL: 127.0.0.1:5548/collabspace. Redis: 127.0.0.1:6399.

Use owner@acme.dev, admin@acme.dev or member@acme.dev with the local-only synthetic password `Passw0rd!`. Open a project and choose 协作文档 (Documents). The user interface currently uses Chinese; English localization is a separate scope.

The helper initializes a new development database only. Production requires reviewed migrations, independent credentials, TLS, correct WebSocket reverse-proxy settings and a tested backup/restore procedure. Archived deployment workflows cannot deploy automatically from this repository.

## Verification

```text
pnpm --filter @teamspace/api build
pnpm --filter @teamspace/api test
pnpm --filter @teamspace/web test
pnpm test:collab
node node_modules/@playwright/test/cli.js test
node scripts/collab-load.cjs
```

The collaboration test runner uses the isolated database configuration generated by local:up. Without that configuration, database tests are explicitly skipped. Browser tests use Microsoft Edge and three independent authenticated browser contexts. The default load run is 15 minutes with 20 sessions across 10 documents, followed by a 20-session hot document.

See [implementation notes](IMPLEMENTATION_NOTES.md) for storage tradeoffs and [requirements](REQUIREMENTS.md) for acceptance criteria. Actual results belong in evidence/collaboration; planned criteria are not evidence of passing.

## Boundaries

The current architecture is single-node. Redis is inherited infrastructure for OAuth/IM, not a durable collaboration log. There is no offline first-load service worker, anonymous sharing, AI writing, whiteboard, live billing acceptance or automatic history compaction. A full current-state snapshot on each commit deliberately favors recovery simplicity over write efficiency; capacity reports must be read with that tradeoff in mind.
