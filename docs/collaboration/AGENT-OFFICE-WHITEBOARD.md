# Office 与白板的 Agent 协作设计

当前实现包括 Office AI 草稿与润色、DOCX 差异审阅、原文件写回、私有副本、办公与白板语音输入，以及自由画布的受控 Agent 操作。

## 本轮实现范围

- 原文件写回先退出当前编辑器并等待 Office 确认所有会话结束。事务内重新核验编辑权限、关闭状态和整个基础文件版本；基础内容有变时要求重新预览。成功产生新版本及审计记录，同一提案网络重试返回同一版本。协作会话仍活跃时可保留提案并另存副本。
- DOCX 支持前 200 个正文段落内由多个样式文本片段构成的混合格式段落。保留未变前后缀所在片段的格式，替换部分继承首个受影响的片段。表格、域、修订、链接等嵌套结构仍有支持边界。
- Office 和白板内的听写使用当前项目语音任务。确认转写前音频留在浏览器。结果进入可编辑提示词，调用模型或保存成果由用户单独确认。
- 自由画布支持新增便签、移动图元和连线。服务端从已保存白板读取所选范围并复查权限和版本。前端验证操作与坐标，用户确认后提交一笔可整体撤销的 Yjs 事务，收到协作回执后显示已保存。Mermaid 源码编辑沿用独立工作区。

## 上一轮交付记录

- Office 和协作文档编辑页默认收起桌面项目导航，编辑页提供打开导航的按钮。Office 文件管理和编辑工具说明位于编辑器下方。宽屏并列显示编辑器与 AI 面板，窄屏限制面板高度并内部滚动。白板画布高度随视口调整。
- DOCX 首批支持正文中前 200 个段落里仅含一个普通文本 run 的段落。段落和 run 的样式属性保留。混合格式、多 run、表格、字段和修订待单独支持。
- 提案绑定组织、用户、文件、已保存版本、段落位置和前后文本摘要，签名有效期 30 分钟。生成前后都检查访问权限。用户确认时再次核验权限并复用私有副本的事务、幂等回执和审计。
- 原文件后续产生了新版本时，用户仍可按预览中的旧版本创建私有副本，也可以重新读取最新已保存版本。侧栏提示版本变化。副本成功后可以在新标签页打开，原编辑会话随当前页保留。

## 界面和行为

- 顶部显示资源名称、保存状态和版本入口。宽屏上左侧 Agent、右侧编辑器，窄屏保留编辑器并用抽屉打开 Agent。用户可拖动分隔线。切换面板时编辑器实例保持挂载。
- Agent 面板顶部显示当前操作范围，例如「本文件」「销售表 B2:F12」「已选 3 个图元」。范围随请求固化，之后切换选区仅影响下次提交。
- 输入区提供麦克风、润色和发送。润色返回可编辑的替换建议，提供「采用」和「还原」。规范化目标、范围、要求和验收条件，保留用户给出的事实与语言；关键信息缺失时在建议里标出。润色和听写均只更新输入草稿。草稿生成期间的后续手工输入保留，用户可自行合并。
- 对话中每次修改显示成果卡，标记「生成中」「待审阅」「冲突」「已应用」或「失败」。点击成果卡可定位相关段落、单元格、幻灯片或图元，并预览差异。「应用更改」「保存为副本」「放弃」明确分开；长列表才使用可搜索选择控件。

## 实现与写入协议

- **DeepSeek**。沿用现有服务端模型适配器、组织级可用状态和预算。文件内容作为数据输入。Agent 产出限定的操作参数，执行器校验类型、范围、数量与资源 ACL。运行时现有项目事实读取与新的文件写入能力分别授权。润色使用独立的纯文本动作，仅接收当前输入。
- **Office**。预览前绑定文件 ID、基础修订和稳定目标，例如文档段落引用、工作表与 A1 地址、幻灯片与对象 ID。申请应用时重新读取权威修订，校验目标的原值和编辑会话状态。通过现有格式引擎产生候选版本，持久化成功后返回实际版本 ID。活跃会话中存在未落盘内容、引擎无法确认保存或修订已变时，应用进入冲突，用户可刷新后重新预览或另存副本。
- **格式保真**。首批分别验证 DOCX 的文本与样式、XLSX 的字面量与公式、PPTX 的文本与版式。默认只允许业务层列出的操作。宏、复杂对象或未支持的内部结构显示具体限制。编辑器重新打开生成版本并检查未触及区域后，才计入该格式验收。
- **白板**。沿用现有 Yjs 图元 schema 和权限。用选区快照生成受约束的图元增改操作，提交时检查目标及引用，写成单次协作事务，经服务端 ACK 后标记已应用。合并无关图元的并行编辑；目标图元发生变更时要求重新审阅。撤销操作只回退本次 Agent 变更。
- **语音**。把 IM 听写的录音、确认、取消和草稿回填复用到共享输入组件。语音任务需要新增按项目及目标资源授权的 Agent 输入范围。复用现有 Azure 适配器；供应商未配置时保留文本操作和实际状态。录音内容只在用户确认转写时提交。
- **重复提交与审计**。同一提案应用采用幂等键。应用记录组织、资源、操作者、模型、基础版本、提交版本、trace ID 及动作摘要。阅读和写入分别进行授权，撤权后未提交的提案失效。文件和图片始终沿用私有存储与组织访问控制。

## 验收与开发顺序

1. **首条闭环**。做共享分屏、文本输入与润色、DOCX 单个段落替换。双账号验证手工编辑、差异预览、应用、保存、刷新后重开；第二人改了同一目标时出现冲突，可另存副本。
2. **语音与白板**。同一输入区验证录音、取消、转写回填、编辑后发送。对白板验证新增、移动、连线、同步、刷新和撤销，以及 Viewer 权限拒绝。
3. **扩展到 XLSX 和 PPTX**。对每种格式跑编辑器往返、格式保真、组织隔离、授权撤销、重复应用、供应商取消和失败场景。先用确定性模型替身，再用合成文件测试真实 DeepSeek。
4. **图片**。复用私有附件采集可作为独立增量。视觉识别需要能处理图片的模型接口、文件访问撤回和明确的外送授权。分别验收附件收取与模型读图。

### 工作台交互

1. **进入**。从协作空间点击资源即打开原编辑器。编辑器内提供「AI 协作」按钮。面板打开后显示当前目标和来源标签，键盘可打开、关闭和返回编辑器。手机使用「编辑 / AI」两个按钮保留输入草稿和当前页。
2. **限定上下文**。默认范围为显式选择的段落、单元格区域或图元。未选定时，可以输入目标位置、在侧栏选段，或显式选用当前文件的已保存版本。只有经用户添加的同项目资料进入首期上下文。请求前可移除每个来源并看到是否将发送给模型。
3. **描述目标**。自然语言可以直接发送。润色建议把目标、上下文、操作范围、限制和预期交付分开，支持复核后采用。缺目标时发出澄清，缺源数据时指出具体缺项。语音转写、文本润色和正式提交各自拥有独立状态。
4. **审阅成果**。每张变更卡展示来源、对象位置、改前改后和产生的影响。首期每个提案对应一个原子提交单元。用户若只想应用其中一部分，先重新生成较小提案，或把多项工作拆成独立提案。多文件任务后续单列各成果、提交状态和失败原因。
5. **确认与恢复**。成功后导航到实际提交版本，用户可以继续手工编辑。撤销 Office 更改创建一条带来源的新修订，前提是目标仍可安全恢复；白板按本次操作的范围撤销。连接断开时重查任务与提交状态，避免二次写入。

### 运行、权限与持久化

| 对象 | 需要保留的字段 | 决定状态的系统 |
| --- | --- | --- |
| 任务 | 用户目标、组织和项目、操作者、选区、来源版本、模型、状态与 trace ID | Agent 运行时 |
| 提案 | 基础版本、受约束操作、旧值校验条件、预览摘要、校验结果、失效原因 | 提案服务 |
| 应用回执 | 申请人、幂等键、结果版本或白板确认编号、错误与重查状态 | 文件版本服务或白板协作服务 |

- 生成状态按「待补充 → 生成中 → 待审阅」推进，另有失败和取消结果。应用状态单独记录为「提交中 → 已应用 / 冲突 / 失败」。提交结果未知时保留「正在核实」，同一幂等键只查原结果。重启后待审阅提案和已提交回执应可查询，生成阶段中断时允许显式发起新运行。
- Viewer 按资源查看权继续手工查看，可用自己的文本草稿。Editor 和 Owner 按目标编辑权提交变更。保存为副本另验目标项目的创建权限。生成前、读取来源前、应用前和读取回执时都校验访问权。撤权后立即禁止查看受限提案内容和执行写入。
- Office 写入需要验证引擎会话已保存且能绑定基础版本。若现有引擎无法可靠证明在线会话已落盘，开放副本路径，同一文件写回能力保持待验。白板提交必须收到服务端持久化确认。Agent 的生成回执与文件保存回执在界面上各自显示。
- 每项操作有明确类型及参数边界。文件正文、附件和模型输出都按数据处理。运行时只允许本次授权的资源与操作。错误记录仅保留所需摘要，原始内容沿用项目资源权限及保留设置。

### 验收门槛与指标

| 编号 | 验收场景 | 通过证据 |
| --- | --- | --- |

以合成项目任务建立纯手工耗时基线，再记录 Agent 辅助完成同一任务的中位耗时、首次可用成果比例、应用失败率和人工返工次数。首期先纳入手工协作回归与 DOCX 修改闭环，随后加入白板、XLSX、PPTX 及跨成果引用。会议自动触发、外部写入、BI 数据源和周期自动化进入企业工作流阶段，逐项定义授权与恢复后再启用。
