# Office 产品能力对照与持续交付

2026-10-25 用户要求继续完善Office，力争达到原生Microsoft Office 90%以上产品特性；明确选择Word、Excel、PowerPoint均衡推进。此要求扩展当前Office首版范围，保留既有租户、项目、文件权限及保存栅栏。

## 衡量方式

“原生Microsoft Office全部特性90%”目前没有确定的版本、平台及功能分母，不能凭ONLYOFFICE功能列表或菜单数量宣布达成。本项目先建立下列60项日常办公基线，三类各20项，目标至少54项通过且全部P0门禁通过。该60项是可审查的工程基线，**不等价于微软桌面全量功能的90%**；不能排除难项后仍称全量90%。VBA/COM/第三方插件、Power Query/Power Pivot、复杂外部连接、邮件合并及高级动画等另列扩展门禁，不以此清单代替验证。

每项通过需要：实际页面可操作→结果保存→关闭重开→下载→Microsoft原应用核对内容/结构及关键显示；涉权限项需正常、拒绝和恢复。只有菜单存在或引擎宣称支持，状态为“待验”，不计入通过。既有证据保留日期和样本，不自动迁移为本轮通过。本轮文件操作验证与原生全量兼容验证分别记录。

## 第一批文件操作契约

| 追溯 | 规则 |
| --- | --- |
| P-OFX01 / BR-OFX01 / D-OFX01 / AT-OFX01 | 新增POST `/office/:id/name`，WRITE、有效组织/项目、名称合法、固定扩展名、expectedTitle并发保护；同事务更新collab_document与prj_file，审计仅记录名称哈希。通用文档rename拒绝OFFICE，保证单一写入权威。活动引擎内部标题下一次打开同步，不为改名销毁编辑器。 |
| P-OFX02 / BR-OFX02 / D-OFX02 / AT-OFX02 | POST `/office/:id/copy`，file:manage及原文档WRITE，只复制明确选定的已确认版本，创建私有OWNER副本。复用collab_restore幂等账本，按组织/requestId事务锁，绑定actor、原文档、版本；名称变更重放冲突。原文件、共享授权与未保存编辑不受影响。 |
| P-OFX03 / BR-OFX03 / D-OFX03 / AT-OFX03 | POST `/office/:id/export/pdf`，READ，仅从当前组织/文档的已确认版本取字节。ONLYOFFICE 10+ `/converter/from-file`，服务端签名并上传；客户端不传URL。30秒超时、20MB输出上限、每用户单并发/实例最多2个，不自动重试。转换后再次鉴权，撤权不返回文件。PDF输出不写原文件、不冒充新保存版本，审计含版本/大小不含正文。 |
| P-OFX04 / BR-OFX04 / D-OFX04 / AT-OFX04 | 页面文件操作区明确区分编辑器当前内容与选中服务器版本，隐藏未确认候选；重命名冲突提示核对，副本网络失败保留同一发送意图以安全手动重试；切组织/文档后旧回调不下载或导航。 |

导出依赖服务端引擎10.0且转换服务开启；旧版本/服务不可用明确失败，不降级为假PDF。沿用现有JWT，不新增云服务或模型费用。引擎品牌、许可和并发限制保持原约束。原生下载/打印权限继续关闭，避免新增直接缓存URL通道；用带鉴权的PDF导出供阅读器打印。

## 后续交付顺序

1. 本批共用文件动作、三格式PDF与拒绝/恢复闭环。
2. Word样式/修订/目录，Excel公式/验证/图表，PPT母版/备注/放映的固定样本与真实双人原生流程，三类均衡补缺。
3. 批注与审阅协作、版式打印、复杂格式往返；每类按20项逐步报告覆盖，不只输出功能入口。
4. 单独评估桌面专有生态和授权前置；Microsoft 365原版嵌入仍需官方合作流程，不因个人订阅或本轮授权自动获得接入资格。
