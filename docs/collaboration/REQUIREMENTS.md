## 1. 做什么与为什么

面向 5–30 人远程开发团队及交付客户，构建“项目协作说明书”：围绕需求、技术决策、交付说明和复盘，共同编辑一份可信文档，在原文上讨论，断网后继续工作，重新连接后收敛，重要节点保留可追溯版本。沿用 TeamSpace 的组织、工作区、项目和账号体系，在项目下增加 Documents。

核心闭环：负责人创建需求文档 → 两位成员共同编辑并看见选区 → 客户评论 → 成员解决评论 → 离线成员重连合并 → 创建交付版本 → 误改后从历史创建恢复副本。

首版选择协作文档，不同时开发无限白板、Notion 数据库、完整 Wiki、看板、视频会议或 AI 写作。白板的几何、缩放、图形和移动端交互会分散同步可靠性投入。现有项目管理和 IM 保留作底座，不扩充计费。

## 4. 角色与边界

组织成员关系有效是所有操作前提。文档 ACL 使用 OWNER / EDITOR / COMMENTER / VIEWER：Owner 管理 ACL、归档和版本；Editor 写正文、评论、建版本；Commenter 只读正文并参与评论；Viewer 只读。组织管理员可审计、应急接管并留痕。客户端隐藏按钮不构成权限控制。

客户首版使用组织内受限成员并显式授权文档；不做匿名链接和跨组织分享。项目可见不自动代表文档可见。任何父级停用、项目归档或 ACL 撤销优先于子级授权；最后一个 owner 不能移除。

## 6. 用户界面

左侧为组织/项目/文档列表，中部编辑器，右侧评论与历史抽屉。顶部为标题、在线成员、共享按钮、连接/保存状态。桌面优先，移动端阅读及基础编辑；中文 IME、键盘导航、焦点管理、读屏标签为 P0。

状态文案：正在连接、已连接、正在同步、已保存到此设备、已保存到服务器、离线、权限已撤销、服务器暂不可用。本地落盘成功与服务端 durable ACK 各自驱动状态，不以 socket connected 推断已保存。

## 7. 验收用例

2026-10-20 发布决策：用户接受当前本机约 0.43 秒的多房间延迟作为本次版本基线，先部署并在线上自测。以下原始 300ms 目标及未达标测量保留，不改写为已达标；本次不继续以性能调优阻塞发布。

- AT01：双组织各有项目；篡改任意 org/project/docId 都无正文、评论、历史泄漏。复用现有 RLS 并用非超级用户跑测试。
- AT02：3 个独立浏览器账号同段编辑；重复/乱序更新后语义文档相同；每人撤销仅影响自身可撤销操作，不撤销别人的全部修改。
- AT03：光标/选区随着原文插入移动；断开后 30 秒内离线；多标签去重显示用户但维护多个会话。
- AT04：A 离线 10 分钟修改，B 在线修改；A 重连后双方语义收敛；关闭并重新打开页面可从本地恢复未上传编辑。离线首次启动页面壳不在 P0。
- AT05：离线期间被撤销，重连不得上传或获取新内容；保留隔离的未同步草稿，允许本地纯文本导出，不自动复制到其他组织。
- AT06：评论锚点经过插入仍对应原文；全部删除后可在未定位评论列表找到；重复提交只生成一条。
- AT07：版本预览不可编辑；从旧版本创建新 docId、全新 CRDT lineage 的副本；当前协作者及原文不受影响；ACL 默认仅恢复人可见。
- AT08：Viewer 伪造二进制正文更新被拒；Commenter 不能编辑正文；撤销事务提交后新写入不能成功，包括已经建立的连接。
- AT09：ACK 后立即终止同步进程，重启仍有该修改；持久化失败时无 ACK 且 UI 为待同步；重试不重复产生业务操作。
- AT10：本机/指定测试机上 20 个活跃编辑会话，10 份文档，每客户端每秒 2 次编辑，持续 15 分钟；目标远端可见 p95 <300ms、durable ACK p95 <500ms；另跑单文档 20 人热点。报告硬件、RTT、正文规模、payload、样本数、错误率及 p50/p95/p99。这是目标而非成绩。
- AT11：WS 超限/恶意 payload 有限拒绝，不拖垮其他房间；DB/Redis 故障、进程重启都有明确状态与恢复证据。
