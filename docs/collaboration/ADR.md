# 决策记录：单节点可信协作

状态：已实施；验收边界以 evidence/collaboration/ACCEPTANCE-2026-10-20.md 为准。适用 5–30 人远程开发团队的项目文档，不扩展成完整 Notion、白板或项目管理平台。

## 1. 正文 CRDT，业务元数据用事务与 revision

正文使用 Yjs 与 Tiptap Collaboration：重复、乱序、并发插入由 Yjs 更新语义合并；同一时间两个成员修改同段不采用整篇最后写入覆盖。撤销由编辑器的协作 UndoManager 跟踪本地操作，不能通过恢复旧快照撤销远端全部工作。

标题、评论状态、权限和版本不是任意 CRDT 字段。标题/评论状态带 revision，过期请求返回冲突；权限由数据库授权事务裁决；命名版本只包含已提交 throughSeq。CRDT 收敛不能证明业务意图一致，团队仍需通过评论与命名版本确认交付。

## 2. 提交成功才确认

HTTP 与独立原生 WebSocket 共用 Store。每次正文更新带稳定 UUID；数据库同时保存增量、去重收据和完整状态，COMMIT 成功后才 ACK、广播该差量。客户端先将状态和 pending 原子落入 IndexedDB，再发送。连接成功只证明在线，ACK 才证明这次服务端持久化成功。

同文档收集 10ms 批量提交，减少完整状态编码与提交次数。每个账号仍逐一鉴权，不能因为同房间中已有 Owner 就接受其他账号写入。批次提交失败不确认任一新更新；重试保留原 ID，数据库收据防止重复写入。

完整状态写放大是当前可解释的取舍，尚未压缩增量日志。避免靠关闭 fsync、移除授权查询或提前 ACK 达到延迟目标。容量报告保留未达标样本，开发机 loopback 成绩不能代表生产网络。

## 3. 离线先保存，重连先鉴权

缓存按 origin/账号/组织/docId/schema 隔离。已打开过的文档可离线编辑，正文与 pending 在同一 IndexedDB 事务提交。重新连接先领取单次短期 ticket，验证父级账号/组织/成员/项目与文档 ACL，再交换 state vector 差量。

队列每次仅一条在途，最小间隔 60ms；5 秒无 ACK 断开重试，稳定更新 ID 不变。数据库失败、本地配额失败、过大单条编辑、永久撤权显示不同状态。失权草稿只能隔离保留与导出，不能在服务器绕过权限补传。退出登录停止 provider 并请求删除相应账号缓存；没有 Service Worker，离线首次加载页面壳不属于本版。

## 4. 数据库裁决权限

JWT 给出身份，不给出永久资源授权。每次 HTTP/WS 操作重新检查服务端组织上下文、有效账号/成员、父项目与显式文档 ACL。数据库 FORCE RLS 作为组织隔离防御层，测试使用无 BYPASSRLS 的角色。

父级授权行加共享锁，与停用/归档的更新冲突；文档行锁串行化正文、权限、版本。撤权先提交时，等待中的新写入必须看到新状态并被拒。事务先获得有效授权时，允许该事务按其线性化顺序完成；不把两个并发事务的墙钟请求时间当作提交顺序。

最后一个有效 Owner 不能被移除。停用账号、无父项目访问权的 Owner grant 不能作为可管理文档的替代人；但允许清理这些失效 grant。接收者列表在同一更新事务内批量筛选，提交后仅向该授权集合广播；presence 定期复核，不把客户端姓名作为权威身份。

权限、版本和元数据操作记录 actor、资源、trace_id 与结构化前后状态。标题仅记录摘要，正文、评论内容、ticket 与凭据不进入审计差异。

## 5. 历史恢复创建独立副本

版本为不可变完整状态。预览使用独立只读 Y.Doc，不连原房间。恢复先 materialize 内容，再创建全新 Y.Doc/CRDT 身份及 docId；初始仅恢复人 Owner。恢复请求带幂等 UUID，不覆盖正在编辑的原文，不复制旧评论锚点。

这使版本恢复不需要迁移所有活跃客户端 epoch。原地回滚、双节点 Redis 分发、checkpoint fencing、备份恢复与正式迁移发布均需单独设计和验收。
