# 白板扩展与协作入口设计（2026-10-21）

用户将范围扩展为“协作文档和白板都实现”。本变更覆盖原 REQUIREMENTS/DESIGN 将白板列为后续的范围决定，原文档能力与验收证据保留。

## 产品入口与闭环

侧栏“项目协同 → 实时协作”统一介绍文档与白板，并按当前组织列出服务端授权项目。项目详情分别提供“协作文档”和“实时白板”。文件区只负责附件；消息区是 IM，不代表 CRDT 协作。

在项目创建白板 → 授权组织内编辑者 / 只读客户 → 放置矩形、椭圆、便签、文字、箭头 → 移动、调整大小、改文字/颜色 → 查看在线人员和画布光标 → 各自撤销 → 离线编辑并重连 → 保存命名版本 → 只读预览并恢复为独立私有副本。

## 同步与冲突策略

复用 DocumentProvider、单次 ticket、独立原生 /collab WebSocket、同事务 ACL 和 durable ACK；IM 继续 Socket.IO。collab_document 新增不可变 kind=DOCUMENT/BOARD，已有行默认 DOCUMENT；列表按类型展示，路由依据服务端类型渲染对应编辑器。

每个白板一个 Y.Doc，shapes 是 Y.Map<UUID,Y.Map>。图形字段：type、geometry{x,y,w,h}、text、fill、order。不同对象和不同属性独立合并；geometry 作为一个字段避免并发移动把 x/y 混成未发生过的位置，同一属性按 Yjs 确定性顺序收敛，不宣称理解人的意图。删除 root map key 后，对已删除 nested type 的离线修改不复活图形；撤销是显式用户操作，允许恢复被自己删除的对象。

拖动过程本机即时预览、远端可见光标；松开提交一次原子 geometry 更新，减少写放大。文字修改实时提交；光标使用有限坐标 presence，每 100ms 最多一条，不持久化。视口平移/缩放和选中对象仅属于本地。UndoManager 只跟踪本机命名 origin，远端操作不进入本机撤销栈。

## 权限与持久化

所有白板 CRUD/ACL/评论/版本共享现有文档服务端 org/project/ACL 事务验证及 FORCE RLS。Viewer/Commenter 不可写画布，伪造 WS 更新仍由服务端拒绝。撤权后隔离草稿，可导出本地 JSON，不自动复制到其他组织。评论首版为整板讨论，不冒充对象锚定评论。

服务端解码后验证根类型和图形属性；最多 500 对象、每对象文字 2000 字、有限色板、坐标 ±10000、宽高 20–2000。保留既有帧 360000 bytes、入站增量 256KiB、完整状态 5MiB、慢连接背压。无 HTML 注入、外部图像 URL、任意代码或嵌入执行。恢复版本克隆对象到全新 Y.Doc，保持 BOARD 类型；初始 ACL 仅恢复人，原白板不回滚。

新增列为追加迁移，不改已有状态或授权。API/WS 升级后再发布新前端。Redis 当前用于底座缓存，不声称白板已支持多实例；Pub/Sub 不能代替持久化重放。

## 验收追溯

WB01：可从侧栏找到两类入口，创建的 BOARD 在白板列表出现，旧 DOCUMENT 仍只在文档列表。
WB02：三账号包括只读者；两位编辑者创建、移动、修改不同对象后收敛，Viewer 不能写；真实光标与在线人员可见。
WB03：撤销本机移动不删除远端创建的便签；并发修改不同属性均保留；删除与离线修改后不复活。
WB04：离线本地保存、远端继续操作，重连语义一致；撤权后旧草稿不上传，可导出 JSON。
WB05：命名版本只读预览，恢复新 docId / 新 CRDT lineage、类型保持、他人无访问权；刷新不丢失。
WB06：超限、非法对象、伪造类型拒绝且无提交 ACK；原租户/文档/IM 回归不得退化。

首版边界：不是完整 Figma/Miro；没有自由手绘、图片上传、连接点吸附、对象级评论、匿名邀请、离线首次启动应用壳、多人同对象软锁。没有将文档旧容量成绩当成白板容量成绩，白板 20 人负载需独立测量。
