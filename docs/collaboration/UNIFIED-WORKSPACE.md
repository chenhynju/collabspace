# 协作空间统一入口 — 2026-10-24

## P-HUB / BR-HUB

用户从一个“协作空间”创建、查找和继续编辑富文本、Markdown、白板/Mermaid、Word、Excel、PowerPoint。项目详情使用同一入口并预选项目；旧documents/boards地址保留为同一组件的类型筛选。附件管理保留普通文件下载、共享及旧Office打开路径，移除重复Markdown列表并明确引导协作空间。

## D-HUB

- 全局 /collaboration，项目 /projects/:id/content。统一六种新建选项及上传入口；上传.md/.mmd进入源码编辑器，Office进入原生编辑器，其他文件进入附件管理。文本源码保持UTF-8/BOM/换行规范与服务器长度验证。
- 统一列表按已确认的最近修改时间排序，提供类型/项目/名称搜索，显示类型、项目、最后编辑人、日期和有效文档角色。初始化Office与物理文件按canonical文档ID合并；未初始化文件保留首次打开动作，不重复列出。
- 使用现有服务端组织、项目和文档授权；客户端组织切换时整个内容组件重新挂载并取消旧请求。列表分页每页100条，客户端依次加载，避免原先只显示12条/项目100条而无法找到历史内容。最后编辑人来自真实CRDT更新作者或Office已确认保存审计；未知历史作者显示未记录，不虚构。
- 文件列表项目筛选与服务端accessibleProjectIds取交集，不能由查询参数覆盖已授权范围。未开启协作的原始Office文件仍由上传者首次开启。
- POST /office/create：file:manage + 当前有效组织 + 项目WRITE。独立空白OOXML模板，无宏和外部资源；同事务创建物理文件元数据、Office文档、OWNER授权和初始不可变版本。没有新增表或并行认证/权限模型。
- requestId按组织命名空间关联文件，事务级advisory lock串行化同一创建请求；重放重新验证权限，参数冲突409。不同请求可创建同名独立内容。模板正文也存数据库版本；磁盘写入后事务失败可能留下随机对象键的无引用小文件，不在提交结果不确定时盲删，后续可按数据库引用做审计清理。
- 模板由scripts/generate-office-templates.py生成，清理作者等元数据。Word为空段落、Excel为Sheet1、PPT为一张空白幻灯片。模板源码与生成文件一起归档，无新增线上Python依赖。
- 编辑器保留各自已有实时、保存、评论、权限、版本和离线机制；统一返回协作空间、导航高亮、Office顶部角色/历史/共享入口。没有把Office引擎保存提示冒充应用持久化ACK，也没有新增Office离线编辑承诺。

## AT-HUB

1. 六种类型均可从统一新建入口创建并直接打开；上传.md/.mmd真实保存源码，普通附件与Office正确路由。
2. 最近列表Office不重复；类型/项目/搜索/日期/作者/角色正确；项目和旧地址进入同一界面；移动导航无页面溢出。
3. 三种空白Office通过格式验证和真实原生引擎打开；共享编辑/只读/撤权继续受原规则约束。
4. 并发重试同一requestId只创建一个资源；改参数409；跨组织、受限项目READ、恶意名称与伪造organization_id拒绝；指定无权项目筛选不泄露附件。
5. 回归现有真实非特权PG/WS、单元、完整构建和多账号浏览器，生产备份与回滚后上线，再在线复验。按PASSED/BLOCKED/NOT_RUN记录，不以本地模拟引擎替代真实Office验收。
