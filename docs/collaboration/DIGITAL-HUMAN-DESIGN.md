## 1. 用户决策与范围

本设计承接用户对当前几何人物观感差的反馈，补充并覆盖VOICE-PERSONA.md中“用户可任意选择卡通/真人”的默认归属。两条路线均必须实现，不能以其中一条替代另一条：

| 身份 | 默认外观 | 素材来源 | 必交付能力 |
| --- | --- | --- | --- |
| AI Agent | 类似豆包的亲和、简洁、精致卡通气质，独立原创角色 | 正式美术资产、绑定和动作 | 静态头像、半身3D、自然待机/聆听/思考/讲话、语音同步、真实运行状态 |
| 真人同事 | 本人的写实数字分身 | 本人授权照片或视频 | 照片生成、视频创建、本人预览选择、合成视频及受限实时展示、明确合成标识 |
| Skill | 能力图标/卡片 | 产品图标体系 | 显示所属Agent或实际调用者，不另造“同事”身份 |

“类似豆包”是视觉方向，不推断豆包内部技术，不复制其头像、名称、模型或声音。本期交付设计文档，不自动生成外观样稿、开通付费供应商、训练真人模型或发布代码。既有部署授权不等于某位同事已授权使用人脸/声音。

首发范围含IM、邮件与协作助手/Agent面板；不实现数字分身替本人自主决策、代接所有会议、实时换脸或任意照片克隆他人。真人实时展示是明确标记的合成播报，不冒充本人正在摄像头前说话。

## 4. 卡通角色的美术与资产设计

### 4.1 视觉规范

采用亲和的成年职场助手形象：圆润但不幼儿化，清晰五官和有层次的头发，柔和材质，简洁服装，避免廉价塑料感。初版设计3个同一艺术风格的候选角色，先选1个作为默认并完成制作，其余至少保留可切换的静态头像；角色库扩展不阻塞默认角色的完整动态验收。

画面以胸部以上半身为主；正面略带自然角度，镜头与眼睛大致平齐。头部占舞台高度约35%–45%，保证手机上眼睛/口型可辨认。背景采用产品中性色或透明合成，柔和主光与补光，统一曝光和色彩；浅/深色主题分别验证。表情克制，避免持续摇头、大幅摆动、无语音夸张张嘴。

交付资产：正面/侧面/三分之四视角稿、头像裁切、半身建模、材质贴图、骨骼、表情、动作、渲染预览及授权清单。AI生成的概念图片只用于外观探索，不能宣称已经交付可动3D模型。

### 4.2 技术规范

- 延用Three.js + @pixiv/three-vrm；正式资产优先VRM 1.0。先验证骨骼/表情兼容再锁定生产资源；GLB仅作为经验证的可选导入管线，不同时维护两套默认角色运行器。
- humanoid骨架；至少支持blink/blinkLeft/blinkRight、aa/ih/ou/ee/oh及中性/微笑/专注表情。viseme映射由每个资产包声明，不能假定Azure的22类口型与VRM五元音一一对应。
- 具备idle、listening、thinking、speaking、acknowledge等剪辑；状态间平滑混合。执行/完成/失败以UI真实状态为准，动作只传递气质，不替代结果证据。
- 自然呼吸约4–6秒周期，眨眼随机约3–7秒，视线轻微变化；均为可调整设计参数，非供应商能力声明。尊重prefers-reduced-motion，提供关闭动作选项。
- 起始性能预算：单角色模型压缩后≤8MiB、贴图以1K为主/至多2K、总三角形目标≤60k；正式支持桌面目标30fps以上。以实际设备测量为准，超预算须优化或明确修改预算，不能靠提高上限“验收”。
- 每个角色包包括model、poster、thumb、animations、expressionMap、cameraPreset、licenseRef、revision与SHA256；所有资源同版本发布。内置公开角色可CDN缓存；用户上传素材走私有资源，禁止混用缓存策略。

### 4.3 角色制作门槛

先出候选外观稿和静态场景，再做模型/动作，再接语音。美术验收需用户或明确指定产品负责人对默认角色认可；这是后续交付检查点，不是本次写文档的前置审批。不得再次把几何拼接人物当作成品，缺资产时显示规范的静态头像和实际可用功能。

## 5. 真人同事数字分身

### 5.1 照片与视频均为正式路径

本人从个人设置“我的数字分身”进入：说明用途与处理地区 → 本人授权 → 选择照片/视频 → 素材检查 → 创建任务 → 本人预览 → 发布为本人组织内分身。管理员可禁用功能或撤销组织使用权，不能代替本人做授权或悄悄替换其形象。

照片路径：正脸清晰、单人、无遮挡，避免强滤镜/过曝；供应商决定允许尺寸及格式，前端从服务端能力接口读取约束。输出优先头肩视频，不能承诺照片能生成可靠全身动作。

视频路径：提供实际选定供应商的录制脚本、时长、分辨率、站位、光照与授权声明要求。上传前校验编码/时长/大小，服务端重新校验并隔离转码；不能把某一供应商的2分钟/10分钟要求写死为通用规则。训练可能分钟/小时级，显示真实任务状态，允许离页恢复，不伪造进度百分比。

本人比对身份相似度、发际线、眼神、牙齿、轮廓和肤色，试听中英文示例、数字/人名、停顿和长句；可重做或不发布。真人身份不可自动绑定上传图片中“识别出”的其他同事。

### 5.2 授权与内容确认

- Consent记录用途、人物主体、处理服务/地区、授权版本、到期/撤回、授权证据引用。形象授权与声音克隆授权分别记录；有照片不等于获准克隆声音。
- 默认使用明确标注的标准合成声音；声音复刻是可选独立能力，不影响两种形象路径交付，但不得标注“本人原声”。
- 合成内容持续显示“某某的数字分身 · AI合成”，历史卡片也保留标识；本人录制的原视频与合成视频使用不同类型。
- 真人同事的发送者必须是本人，且先确认最终文字/音轨/视频版本；编辑文字或换声音/形象后确认失效。Agent不得借真人外观自动向同事发言。
- 如未来明确授权分身代本人回答，需独立需求和权限制定；当前只做本人控制的内容制作与展示。
- 撤回、离职或成员禁用立即拒绝新创建/播放会话并停现有会话；撤销分身授权不更改原消息的文字作者，视频访问撤销应显示原因。已下载/收件人保留的副本无法远程收回，产品说明这一实际边界。

两地区都需提供两种产品形象。地区策略以用户组织部署设置和服务端允许列表为准，不按浏览器语言猜测；Azure全球与中国云账号/端点分开，不能承诺中国云具备全球Avatar全部能力。所选地区缺能力时标记该路线BLOCKED，选择满足约束的适配器；不得默默把照片或音频送往另一地区。供应商选择看实测效果/延迟/成本/删除能力，不把宣传页能力当验收结果。

### 6.1 两种驱动方式必须分开

A. audio-driven：Azure生成唯一权威音轨及其hash/revision → 真人供应商消费同一音轨 → 返回含对应音轨的视频/媒体流。归一化PCM是派生格式，保留父音轨hash，不重新TTS。校验输出时长/对齐，播放视频内音轨，不能同时播放原音频形成回声。

B. provider-text-driven：Azure原生Avatar接受冻结的文本/SSML、声音与形象配置，产出的音视频是唯一权威播放物。禁止先单独TTS后期待Avatar重合；预览与确认绑定最终音视频，记录实际voice/provider/文本hash，不虚称消费了先前audioAssetId。

能力接口声明inputModes、photo/video支持、batch/realtime、viseme类型、声音、语言、地区、素材限制及取消/删除策略。若一个供应商不能覆盖两种素材，允许同一产品采用两个适配器完成，但用户身份和确认流程统一。

## 7. 语音、嘴型与状态同步

卡通链路：输入确认 → Azure TTS SDK合成并收集viseme/audio offset → 持久化音频与口型轨道 → 同一播放器时钟驱动表情。服务端校验文本/声音/语言/供应商配置版本，客户端不持有长期供应商密钥。

- 卡通音轨manifest：utteranceId、organizationId、subjectId、textHash、voiceConfigRevision、personaRevision、audioAssetId/audioHash、durationMs、visemeTrackAssetId、trackFormatVersion。访问权限由服务端确认，不信任manifest中的orgId。
- viseme的Azure offset单位转为毫秒；以audio.currentTime/AudioContext播放时间查询轨道，插值与共发音平滑。不是以事件到达时间直接张嘴；暂停/seek/倍速/缓存等待时与实际播放时钟同步。
- 资产expressionMap将viseme映射到可用表情权重，限制权重范围；静音口型归零。头部动作/眨眼与唇形分层，不互相覆盖。音色或语言不支持精确轨道时展示“基础口型”或静态降级，不能冒充精确同步。
- 播放状态idle/loading/playing/paused/stopped/error与Agent运行状态分开。运行completed之后仍可能播报；播放结束不得把任务标成completed。沿用可信运行事件sequence/resultRef验证，未来添加subject/run/utterance关联并提供旧事件适配，不直接破坏现有version:1消费者。
- 停止播报立刻停止音频与口型并清队列；取消Agent任务走原运行时接口单独确认。切组织/账号/页面、撤权、隐藏页面释放私有音频、订阅和会话；恢复需重新鉴权。
- 一次只允许一个有声舞台。当前全局collabspace:voice-level事件需替换为按组织/subject/utterance作用域的播放器订阅，避免同事声音驱动错误人物；兼容期旧事件只供旧预览，不接新正式舞台。

## 10. 任务恢复、费用与安全

创建状态：DRAFT → CONSENT_REQUIRED → VALIDATING → QUEUED → CREATING → REVIEW_REQUIRED → READY；拒绝/失败/取消/撤销另有终态。发布必须由本人审核确认。渲染状态：QUEUED → RUNNING → READY，另有FAILED/CANCEL_REQUESTED/CANCELLED/UNKNOWN；撤销期间任务到达不得再转READY供播放。

数据库CAS/version保证唯一终态与租约；Redis只做调度。未知结果保留providerRequestId先查询核对，不自动重建收费任务。创建训练与每段播报分别预占预算，按实际账单结算，组织/个人/供应商并发和分钟数可配置；无额度时拒绝新任务。重试只用于已确认无副作用或幂等安全的错误，有次数/退避上限。

取消API不保证供应商已停止计费；界面区分请求取消、已确认取消、结果未知。超时会话后台清理，页面关闭必须触发stop并有服务端TTL兜底。回调晚到只更新核查/费用记录，不复活已撤销身份。

所有查询带服务端组织验证和RLS，媒体访问额外检查文档/消息/收件人权限。审计actor、subject、资源、前后版本、provider、traceId；不记录人脸素材、原始声音、密钥和签名URL。授权证据加严权限，供应商原始素材/模型/生成物的删除分别跟踪，不能用本地删除成功冒充供应商删除。

初始保留策略：未提交本地录音沿用现有24小时目标；新真人原素材在创建完成/失败后默认7天清理，生成草稿默认24小时，已确认消息媒体随原消息保留。具体供应商要求和组织保留策略冲突时创建前阻止并解释；这些是待实现产品策略，不是现存清理能力声明。撤销立即阻止访问，后台删除有可查询收据；备份随既有备份到期清除，明确已下载副本和备份删除延迟。

## 11. 效果与性能验收门槛

以下数字为产品目标，必须记录设备/浏览器/地区/网络/供应商版本及样本数，失败则保持BLOCKED或修订规格，不预填PASSED。

| 项目 | 目标与方法 |

## 13. 模块归属、交付顺序与剩余项

仍为独立模块融入现有体系：前端personas拆分PersonaIdentity/CharacterStage/EmployeeAvatarWizard/PersonaLibrary/PlaybackController；voice保留录音/播放基础；api在现有voice下或同域personas模块逐步扩展，避免重复任务/媒体服务；共享协议复用已存在的workspace协议包，只有确有跨包消费时提取新包。

1. 设计阶段（本次）：完成本文件及入口追溯、核对供应商能力来源；不宣称美术或真实调用完成。
2. 资产阶段：原创角色外观稿与正式默认模型、静态头像、动作/表情包；同时做真人供应商准入、两种素材/两地区能力表及本人授权采集指南。
3. 卡通实现：替换占位、懒加载和按需舞台、Azure viseme真实轨道、作用域播放器、可信Agent状态；先通过DH01–03/10。
4. 真人实现：授权与私有素材、照片和视频创建任务、本人审核、渲染/会话、确认发送、撤销删除；覆盖DH04–09。不能将视频路线无限期列“未来”。
5. 集成发布：双账号/组织、断网/恢复、原IM/邮件/Agent回归和资源抽样；仅通过实际门槛后发布，版本与回退可追溯。

剩余配置：Azure Speech账号与中英音色/viseme矩阵、Avatar访问资格与配额、国内适配器、正式角色资产、授权真人样本、私有存储保留/删除策略、会话预算、参考设备。涉及付费开通和本人素材授权按实际需要解决，不妨碍先完成本设计和无外部副作用的开发。
