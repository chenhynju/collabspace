# 协作快照时间轴

2026-10-29，P-SNAP：富文本、Markdown 和白板按时间查看持久快照。Office 沿用独立引擎版本，不接入 Yjs 快照。

## BR-SNAP / D-SNAP

- 服务端在正文更新事务内创建 AUTO 快照，首个成功编辑立即采样，之后距上次自动快照至少一分钟的首个成功编辑再次采样；空闲时不生成。单条更新与批量提交共用逻辑，批次取最终提交状态及最后一个编辑者。
- 每个快照保存独立完整 Yjs 状态及服务器 seq，创建后不可变。重复 updateId 不新增，正文事务失败时快照与审计一起回滚。采样不是逐键录制，也不保证最后一次编辑恰好成为自动快照；用户可点“立即保留快照”保存当前确认节点，或创建命名版本。
- MANUAL 版本保留原行为。时间轴按服务器 created_at、id 排序；每页100条，以 before=快照UUID游标加载更早记录，重复时间戳不漏项。自动与手动节点均支持只读预览、前后切换及恢复为独立私有副本。
- GET /documents/:id/versions?before=UUID 沿用组织、成员、项目、文档实时授权；预览和恢复继续分别鉴权，撤权后旧节点不可再次读取。快照存放于现有 FORCE RLS 的 collab_version，审计仅写节点ID、seq及来源。
- 增量迁移新增 source（AUTO/MANUAL，旧行默认 MANUAL）和时间轴索引。先迁移数据库，再更新 API/WS 和前端。所有 INSERT 使用显式列名；应用回退需保留显式列名兼容补丁，原始无列名 INSERT VALUES 不兼容新增列。回退保留新增列和数据，不删除快照。
- 不把此前未保存的编辑补造为历史快照，不新增自动清理策略。完整状态存在存储成本，应按实际文档大小监测容量。

## AT-SNAP

1. 单条/批量成功提交生成可解码快照；重复、分钟内编辑不重复采样；早期状态不随新编辑改变。
2. 时间轴、前后预览、即时快照与私有副本恢复可实际操作；原文档保持当前状态。
3. 同时间戳超过100条时游标完整翻页，无重复遗漏。
4. 无文档权限拒绝列表，Viewer 可读不可恢复；撤权后拒绝预览；恢复副本不向原Viewer开放。
